# ChatGPT certificate checker and soundness proof

`C16Frames.CertGPT.no_swap_frame` proves that the actual 720 × 720 pool Gram
matrix has no swap-invariant pair frame of size 128. The matrix is the F₂-valued
version of `parity (xArr[i] &&& zArr[j])`; `bitZ` identifies false/true with 0/1.
The theorem compiles with no `sorry`. Final `lake build` succeeded (3,833 jobs,
exit 0), and all 13 final executable tests passed.

Branch: `independent/c16-lean-cert-chatgpt-20261107`, based on research commit
`7cdf520a98801f24bd5c9cbd33f0373be33549ff`.

Author: OpenAI ChatGPT. The exact model/version identifier is not exposed to this
execution; no more specific identifier is asserted. Toolchain:
`leanprover/lean4:v4.36.0-rc1`; Mathlib
`5f7b4198d22a9c82e1c698a379334fe128095c82`.

## Files and trust boundary

* `CertGPTKernel.lean`: total fuelled tree checker; ordered C/K children, explicit
  eligibility, positive need, F/S rejection. `check_sound` and
  `check_no_completion` have explicit `RulesSound` hypotheses. Ten small kernel
  reduction tests exercise branches, fuel, sibling exclusion and rejection.
* `CertGPTBits.lean`, `CertGPTRank.lean`: executable parity and Gaussian span
  counter, with proofs relating them to coordinate dot products and matrix rank.
* `CertGPTCheck.lean`: unsharded swap/quarter orbit regeneration, table validation,
  R/E/B checking, sibling exclusion, K validation, and FRAME reporting. Both a
  flat-stream runner (with statistics) and an adapter to the proved tree kernel
  are provided. Rank leaves use the permitted one-sided vector-rank upper bound.
* `CertGPTData.lean`, `CertGPTGen.py`, `CertGPTTest.lean`: strict authenticated
  input conversion and executable harness. SHA-256/gzip/text parsing in Python
  are outside the formal kernel; the Lean checker rechecks orbit/table content.
* `CertGPTFrames.lean`: generic pair frames, projection to `C16Frames.IsFrame`,
  swap-orbit decomposition/disjointness/partial-frame facts, and outer-product
  identity for a full-cardinality frame.
* `CertGPTFrameCheck.lean`: executable partial-frame test implies the mathematical
  pair-frame predicate.
* `CertGPTSound.lean`, `CertGPTCompletion.lean`: residual parity, coverage, removal,
  size and live-state transitions, the concrete completion invariant, and its
  proved `RulesSound` instance.
* `CertGPTRankLeaf.lean`: R-leaf soundness from the induced matching bound and
  the proved Gaussian span counter.
* `CertGPTItemTable.lean`, `CertGPTRoot.lean`: executable table validation gives a
  disjoint orbit partition; the frame identity establishes the initial residual.
* `CertGPTSwapData.lean`, `CertGPTRun.lean`, `CertGPTPool.lean`: generated encoded
  swap data, native checked acceptance, and exact PoolData equality.
* `CertGPTNoSwap.lean`: finite-index bridge and final `no_swap_frame`.
* `CertGPTVertex.lean`: exact equivalence with the existing `IsFrame` matching
  representation and transfer to swap-fixed `(S,T)` frames via `fixed_swap_iff`.
* `CertGPTAudit.lean`: axiom audit of the components and final theorem.

No hand-written `axiom`, `sorry`, or `admit` is introduced. `CertGPTCompletion.lean`
proves the actual `RulesSound` instance; `CertGPTRoot.lean` proves root completion
from a bounded swap frame and the executable table checks. `CertGPTNoSwap.lean`
instantiates the actual `PoolData` arrays and the authenticated certificate.

The exact target axiom audit is:

```
[propext, Classical.choice, Quot.sound,
 swap_check_ok._native.native_decide.ax_1_1,
 swap_pools_ok._native.native_decide.ax_1_1]
```

The last two are generated by the official Lean 4.36.0-rc1 `native_decide`
implementation (`Lean/Meta/Native.lean`); they are its native evaluation trust
boundary, corresponding to the older `Lean.ofReduceBool` description in the spec.
One checks certificate acceptance, the other checks exact decoded vector equality
with `PoolData`. All mathematical soundness, rank, orbit, root and finite-index
bridges use only the standard three axioms. Array sizes are checked by kernel
`decide`, not another native oracle.

## Reuse and independence

Read #77/#78 and files on `independent/c16-lean-cert-20261107` read-only. No edits,
commits or pushes were made to that branch. `CertGPTBits.lean` and
`CertGPTRank.lean` adapt the other branch's `CertRun.lean` / `CertSound.lean`
parity and Gaussian-count implementation/proofs (Grok/xAI), preserving their
mathematics while separating generic vector proofs from concrete pool evaluation.
The projection-to-IsFrame proof in `CertGPTFrames.lean` was informed by its
`CertCheck.lean`; attribution is also in the source. The remaining checker,
generator, tree-kernel proof and orbit/residual bridges were developed here.
The specification explicitly permits this reuse: independence of authorship is
not the Lean trust boundary. The reference Python checker was also permitted.

## Reproduction

From this directory, with the pinned toolchain:

```sh
lake update
lake build
python3 CertGPTGen.py ../restricted-frames-20261031/certificates/swap.inst \
  ../restricted-frames-20261031/certificates/swap.cert.gz /tmp/swap.input
lake env lean --run CertGPTTest.lean /tmp/swap.input swap
```

`lean --run` uses an interpreter and is substantially slower than native code.
The test log records native runs. The parser accepts only a complete unsharded
header and terminal `END COMPLETE`; S records cannot establish acceptance.
Quarter, the three bad fixtures and planted inputs use the analogous command,
with `--pools planted` for planted data and `quarter` for the runner's class.

## Scope and verification

Only the required swap class is formalized. Half-turn and swap-half-turn
certificates are not claimed. The executable also supports the unsharded quarter
known-answer fixtures. F reports a verified frame; S rejects rather than granting
unchecked shard coverage.

See `CertGPTResults.json`, `CertGPTAudit.log`, `CertGPTBuild.log`, and
`CertGPTNoSwap.log` for the actual results. The final theorem does not assume a
soundness predicate or an unproved frame-exclusion hypothesis.

`precompileModules = true` on the separate `CertGPTNative` Lake library is
important: imported core checker helpers are
loaded natively for `native_decide` instead of rerunning expensive loops in the IR
interpreter. `CertGPTTest.sh` separately builds a native test executable in a
temporary directory and tests valid, planted and altered inputs. Python SHA-256
verification is an input provenance check, not an axiom of the final theorem;
the Lean decoder and checked data are connected to the actual pools in Lean.
