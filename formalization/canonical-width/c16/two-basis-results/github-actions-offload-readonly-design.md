A workflow triggered by `push` can be stored and run only on the exact research branch: GitHub reads workflow files from the event's associated commit/ref. In contrast, `workflow_dispatch` requires the workflow to exist on the default branch, so it is unsuitable for a strict branch-only experiment. [Workflow trigger model](https://docs.github.com/en/actions/concepts/workflows-and-actions/workflows), [manual dispatch restriction](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow).

The concrete optional design would be one push-only workflow filtered to `research/c16-two-basis-20261030T1438` and a dedicated reviewed trigger/config path, with a matching job-level branch guard. It would have one `ubuntu-24.04` job, 15-minute timeout, one CPU thread per numerical library, no matrix, no schedule, and a fixed concurrency group with no cancellation of an active evidence-producing run. It would request only `contents: read`, use no stored secrets, persist no checkout credentials, and perform no repository writes, comments, PR operations, deployments or source searches. Parent would review the full workflow before any push, because the initial push itself can launch the run. Repository coordination rules retain the existing immutable claim and parent-owned publication process; this proposal creates no new research ownership or default-branch change.

The runner receipt should bind commit SHA, workflow SHA, input closure, interpreter/library versions, all actual commands, exit statuses and output hashes. Store receipts and bounded logs under the runner temporary directory. Upload only that explicit directory, with hidden files excluded, a unique run/attempt name, a small size cap and one-day retention. The upload step should run after ordinary test failures; a forced runner timeout can still prevent artifact recovery. Artifact expiration is not archival preservation. An eventual downloaded receipt must retain the original mathematical scopes: a green CI status does not upgrade a negative or inconclusive endpoint. [Artifact upload interface](https://raw.githubusercontent.com/actions/upload-artifact/main/README.md), [artifact access and retention](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/download-workflow-artifacts).

Current official documentation says public-repository standard GitHub-hosted compute is free; larger runners are billed. The standard public `ubuntu-24.04` runner has four CPUs, 16GB RAM and 14GB SSD. This does not guarantee memory sufficiency, queue latency or dependency-download success. Hosted VMs have outbound network access needed for GitHub and package retrieval, and Linux runners provide sudo; the proposed job does not need private-network access. [Runner resources/network](https://docs.github.com/en/actions/reference/runners/github-hosted-runners), [billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions).

[Usage limits](https://docs.github.com/en/actions/reference/limits).
